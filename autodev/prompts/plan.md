## 할 일
1. 태스크 문서와 관련 프로젝트 문서, 관련 코드를 읽는다.
2. 태스크 문서의 `## 계획` 섹션을 작성한다. 이미 계획이 있으면 검토 의견을 반영해 고친다.
   - 접근 방법 (3~6줄)
   - 바꾸거나 만들 파일 목록과 각 파일에서 할 일
   - 테스트 계획: 어떤 테스트로 완료 기준을 증명하는지
   - 위험 요소와 대응
3. 설계 선택이 필요하면 가장 널리 권장되는 표준·기본값을 고르고 `## 결정 기록` 에 남긴다.
4. 검증 명령을 확정한다. 종료코드 0 이면 완료로 판정되는 셸 명령이어야 한다.
   프로젝트 기본값은 `{{default_verify}}` 이다. 검증 명령은 코드 디렉터리에서 실행되며
   `$VAULT`, `$PROJECT_VAULT`, `$TASK_FILE`, `$CODE_DIR` 환경변수를 쓸 수 있다.
5. 계획은 한 번의 구현 세션으로 끝낼 수 있는 크기여야 한다. 너무 크면 이번 태스크에서 할 범위를 줄이고,
   남는 일은 `## 계획` 끝의 "후속 작업" 목록에 적는다.

사람만 풀 수 있는 문제가 있으면 `status: blocked` 로 반환하고 `human_action` 에 필요한 조치를 적는다.
그렇지 않으면 `status: planned`, `verify` 에 확정한 검증 명령, `summary` 에 계획 요약 1~2문장을 반환한다.
