## 할 일
1. 태스크 문서의 `## 계획` 과 `## 검토` 를 읽는다. 검토 의견은 반영한다.
2. 계획대로 구현한다. 코드 태스크라면 테스트를 함께 작성한다.
   조사·문서 태스크라면 산출 문서를 프로젝트 볼트 폴더에 쓴다. 조사 결과에는 출처를 적는다.
3. 검증 명령을 직접 실행해 통과시킨다. 실패하면 원인을 고치고 다시 실행한다.
   검증을 통과시키려고 테스트를 지우거나 약하게 만들지 않는다.
4. 태스크 문서를 갱신한다.
   - `## 구현 로그`: 바꾼 파일, 핵심 변경, 실행한 검증 명령과 결과
   - `## 완료 기준`: 충족한 항목의 체크박스를 채운다
   - `## 완료 보고`: 무엇이 되었는지, 남은 일과 후속 작업, 알려진 한계
5. 프로젝트 문서를 갱신한다.
   - 진행 이력 문서(`memory/progress/changelog.md` 가 있으면 그곳, 없으면 만든다)에 날짜·결정·이유를 기록
   - 프로젝트 TODO 문서에 해당 항목이 있으면 체크한다
   - 구조나 설계가 바뀌었으면 해당 설계 문서와 INDEX 를 고친다
6. git 커밋·푸시는 하지 않는다. 드라이버가 한다.

## 반환
- `status: done` — 구현을 마쳤고 검증 명령이 통과했다.
- `status: failed` — 시도했지만 검증을 통과시키지 못했다. `summary` 에 원인과 다음에 시도할 것을 적는다.
- `status: blocked` — 사람의 조치가 필요하다. `human_action` 에 구체적으로 적는다.
- `commit_message`: 저장소 관례(`feat: …`, `fix: …`, `docs: …` + 한국어 설명)에 맞춘 한 줄.
- `summary`: 결과 요약 1~3문장.
