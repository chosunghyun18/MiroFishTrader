# 단계: 태스크 분해 (SPLIT)

프로젝트 **{{project}}** 의 작업을 자동 개발 루프가 하나씩 처리할 수 있는 태스크로 나눈다.
이 단계에서는 **어떤 파일도 수정하지 않는다.** 읽고 조사해서 결과만 반환한다.

{{ssot}}

## 규칙
1. 태스크 하나는 **한 번의 구현 세션(대략 반나절 이내 분량)** 으로 끝낼 수 있는 크기여야 한다. 크면 더 쪼갠다.
2. 태스크마다 **기계가 판정할 수 있는 검증 명령**(`verify`)을 정한다. 종료코드 0 이면 통과다.
   - 코드 태스크: 테스트 명령. 프로젝트 기본값은 `{{default_verify}}` 이다.
   - 조사·문서 태스크: 산출 문서의 존재와 필수 섹션을 확인하는 셸 명령.
     예: `test -s "$PROJECT_VAULT/research/data-sources.md" && grep -q "^## 결론" "$PROJECT_VAULT/research/data-sources.md"`
   - 검증 명령은 코드 디렉터리에서 실행되며 `$VAULT`, `$PROJECT_VAULT`, `$TASK_FILE`, `$CODE_DIR` 환경변수를 쓸 수 있다.
3. 프로젝트 문서가 정한 순서·게이트를 지킨다. 선행 단계가 안 끝났으면 그 뒤 단계의 태스크는 만들지 않는다.
4. 사람만 할 수 있는 일(키 발급, 계정, 결제, 실거래 판단)은 `needs_human: true` 로 분리하고 `human_action` 에 할 일을 적는다.
5. `depends_on` 은 이번에 반환하는 `tasks` 배열 안의 **0부터 시작하는 인덱스**다. 선행 태스크가 앞에 오게 정렬한다.
6. `priority` 는 1(가장 먼저)~5. `kind` 는 `code` / `research` / `docs`.
7. 한 번에 최대 8개. 지금 착수할 수 있는 것만 만든다. 할 수 있는 일이 없으면 빈 배열을 반환하고 `notes` 에 이유를 적는다.
8. `goal` 은 무엇을 왜 하는지 2~4문장, `acceptance` 는 확인 가능한 완료 기준 목록이다.
9. **진행 중인 다른 작업과 겹치지 않게 한다.** 프로젝트 볼트의 `task/` 폴더에 `status: in-progress` 인 문서
   (`task/autodev/` 밖의 문서 포함)가 있으면 사람이나 다른 세션이 그 범위를 작업 중이다. 그 범위는 태스크로 만들지 않는다.
   그 작업의 결과물에 의존하는 태스크는 해당 코드가 이미 커밋되어 코드 디렉터리에 존재할 때만 만든다.

결과는 지정된 JSON 스키마로만 반환한다.
